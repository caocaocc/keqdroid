# Как работать в keqdroid

Flutter-клиент прокси/VPN: Android, Windows, Linux. ~59 000 строк в `lib/`,
1000+ тестов. Хозяйка проекта не программист и код не читает — **она проверяет
приложение, а не диффы**. Из этого следует всё остальное в этом файле.

## Правила работы

**Не писать по памяти.** Идиомы Dart и стиль — по [Effective
Dart](https://dart.dev/effective-dart). Поведение виджета, значения по
умолчанию, тонкости жизненного цикла — по [api.flutter.dev](https://api.flutter.dev),
а не по воспоминанию о том, как оно обычно бывает. Не уверен — открой и прочитай,
это дешевле одного неверного предположения в чужом коде.

Оговорка: документация Flutter молчит про предметную область этого проекта.
Как ведёт себя xray при неизвестном geo-коде, почему mihomo отваливается на
`minClient`, что происходит с wintun-адаптером при чужом GUID — на это отвечают
только сам код, его комментарии и тесты. Там источник истины здесь, а не портал.

**Объяснять почему, а не что.** Комментарий, пересказывающий код словами, —
мусор. Комментарий обязан отвечать на вопрос, который возникнет у того, кто
захочет это переписать: почему сделано именно так и что сломается иначе. В
проекте уже сложилась эта культура, держись её уровня — например,
`themeAnimationDuration: Duration.zero` в `lib/app/app.dart` объяснён замером в
55 мс на Pixel 6a, а не фразой «анимация отключена».

**Уборка не меняет поведение.** Если правка меняет то, что видит или чувствует
пользователь, это не уборка, а новая задача — её обсуждают отдельно. Перед
входом в опасную зону (см. ниже) сначала пишутся тесты, фиксирующие текущее
поведение, и только потом двигается код.

**Проверять фактами, а не уверенностью.** Утверждение «эти две функции
одинаковы» проверяется по всем веткам, включая фолбэки на `null`. На этом уже
была ошибка в прошлом заходе уборки.

**Отчитываться так, чтобы было понятно без чтения кода.** Что изменилось, что от
этого меняется на экране (обычно — ничего), чем это доказано.

## Базовая линия

Держится на каждом коммите, без исключений:

```bash
flutter analyze   # обязан печатать "No issues found!"
flutter test      # весь набор зелёный
```

Тесты повторяют структуру `lib/`. Фикстуры — `test/fixtures/`, помощники —
`test/helpers/` (`pump_app.dart`, `test_storage.dart`).

Приложение после правок **запускает хозяйка**, не сессия. Твоя работа
заканчивается на зелёных analyze и тестах плюс, при сомнениях, сборке.

## Карта кода

| Где | Что |
|---|---|
| `lib/screens/` | экраны; `lib/ui/desktop/` — десктопная оболочка |
| `lib/providers/` | состояние на Riverpod, разложено по темам |
| `lib/services/` | подписки, хранилище, пинг, обновления, соединения |
| `lib/tunnel/` | бэкенды туннеля по платформам |
| `lib/utils/` | генераторы конфигов и парсеры |
| `lib/platform/` | мост в нативный код |

Генераторов конфигов **три**, и это не дубли — у каждого своё ядро и своя схема
владения туннелем: `config_gen.dart` (xray), `mihomo_config_gen.dart` (mihomo,
ядро владеет туннелем само), `singbox_tun_config.dart` (sing-box TUN на
десктопе). Фича, добавленная в один, обычно нужна и в остальных — проверяй.

## Опасные зоны

Сюда не лезут без тестов, фиксирующих текущее поведение. Ошибка здесь не падает
с исключением, а тихо ломает подключение у пользователя:

- `lib/utils/config_gen.dart`, `mihomo_config_gen.dart`, `singbox_tun_config.dart`
- парсинг подписок в `lib/services/subscription_service.dart`
- `lib/tunnel/*_tunnel_backend.dart`
- `VpnStateNotifier.connect()` в `lib/providers/vpn_state_provider.dart`

Голден-фикстуры на генераторы и корпус входов парсера уже есть
(`test/fixtures/`) — пользуйся ими и дополняй, а не пиши с нуля.

## Мины, на которых уже подрывались

- **Не-ASCII в `.ps1` и генерируемых файлах** ломает сборку и апдейтер на
  Windows (cp1251 против UTF-8). Тире, кавычки-ёлочки, эмодзи — проверяй.
- **`ref` в `State.dispose()`** рвёт unmount до закрытия подписок Riverpod и
  даёт ассерт на каждое последующее изменение провайдера.
- **Свой HTTP мимо туннеля**: пакет приложения исключён из TUN, поэтому прямой
  запрос идёт в обход VPN. Запросы приложения обязаны ехать через локальный
  инбаунд.
- **Исключение в `paint`/`layout`** глушит render object молча: виджет просто
  исчезает, без красного экрана.
- **Релиз без контрольной суммы** апдейтер отклоняет (fail-closed). Он ищет либо
  сайдкар `<имя ассета>.sha256` рядом, либо общий манифест (`SHA256SUMS`,
  `checksums.txt`) — см. `_findChecksumAsset` в `update_service.dart`. Релизить
  через `tool/make_release.ps1`, он раскладывает сайдкары сам.
- После `flutter pub get` перед сборкой под Windows —
  `powershell -File tool/sync_windows_plugins.ps1` (Firebase только под Android).
